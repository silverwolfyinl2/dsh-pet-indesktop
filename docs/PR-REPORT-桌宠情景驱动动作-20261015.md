## 一、核心特性

桌宠的动画链是**概率随机**的（`window.py::_pick_next` 的注释原文：「30% 待机 / 10% 转向 / 40% 动作 / 20% 移动」）。
外部集成方（我们）需要的是「**平时待机**，由我方**按情景指定**播某个动作」——
即**可选择的动作**，而不是随机链。

本次改动提供两条能力，并且**默认关闭**（不改既有行为）：

| # | 能力 | 说明 |
|---|---|---|
| 1 | 空闲只待机 | `PET_SCENE_DRIVEN_ANIM=1` 时，`_pick_next` 不做空闲随机掷骰，只回待机；事件驱动入口（卡住/失败/忙/吃文件/报时）**不受影响** |
| 2 | 情景点名动作 | 事件 JSONL 新增可选字段 `action`：`{"state":"attention","text":"…","action":"悠闲哼歌"}` ⇒ 播**那一个**动作，播完由既有播完逻辑回待机 |

**红线 / 不变量**：
1. **默认关**时行为与既有版本逐字一致（她既有的 4 支预测消费测试必须保持绿）；
2. 名字非法 ⇒ 返回 `False` 且**不改当前动画**（不静默乱播、不抛）；
3. 六态词汇（`idle/thinking/working/attention/error/sleeping`）语义不变，`action` 是**附加**字段，旧写方行为不变；
4. 本次只动动画选择与事件字段；不碰窗口/输入/识屏/碰撞体/几何总线。

## 三、实现要点

**根因（第一次实现失败的原因，值得记录）**：`slow` / `game-copilot` 这两条自定义 agent 由
`CustomAgentMonitor(BaseAgentMonitor)` 读取，其逐行循环在**基类 `_poll`** 内。第一版直接在
`_poll` 里调 `self.win.play_scene_action(...)` —— 但 `self.win` **只在 `AgentLink.__init__` 里赋值**，
监视器实例根本没有这个属性 ⇒ 每次抛 `AttributeError`，被自己的 `except` 吞掉（且是 `log.debug`，
低于 INFO ⇒ **日志里完全看不见**，表现为"点名了没反应"）。

**最终设计（贴本仓既有约定：worker 线程发信号 → 主线程操作窗口）**：
```
JSONL 行 ──(_poll, worker 线程)──> scene_action.emit(agent_key, name)
         ──(Qt 队列投递)──> AgentLink._on_scene_action()  ──> self.win.play_scene_action(name)
```
* 白名单校验放在窗口侧（`play_scene_action`），监视器侧不做判断，避免两处规则漂移；
* `[SCENE]` 两类日志（拒绝 / 已播 + 当前 `anim`）是**本次新增的观测量**，用于机器判定；
* **备选方案（未采用）**：把慢通道逻辑搬进桌宠进程。会让"唯一终态 / 在途上限 / 审计 / 影子期- live 期拆分"
  这些外部纪律脱离控制面，且"桌宠崩＝决策崩"，故不采用。

## 四、性能分析

**方法（可复现）**：`D:\AI\AIWORK\game-copilot\.venv\Scripts\python.exe D:\AI\AIWORK\game-copilot\data\_tmp_t1_measure.py`

| 写入 → 播放（`超大伸懒腰` / `哈欠连天`） | 486 / 486 ms | 同上 |

| 渲染子进程空闲 CPU | **0.28 s / 5 s ⇒ 5.6%** 单核 | **既有**（渲染/事件循环成本，本次未新增线程或定时器） |

**结论（逐条）**
1. **稳态开销**：情景驱动开启后，空闲**不再**做随机掷骰，也不播动作/移动 ⇒ 动画解码负载**下降**；
   空闲态实测未见新增开销（新增的是一次字符串比较 + 一次 `set` 成员判断）。
2. **新增路径成本与频率**：每收到一条**带 `action`** 的事件行才触发一次
   （白名单判断 + `_switch` 一次）+ 一行 INFO 日志；不带 `action` 的行**零额外成本**；
   触发频率由我方控制（实测手动点名 5 次）。绝对延迟见上表（中位 486 ms，主要来自她的轮询周期）。
3. **新的系统调用/网络/磁盘/线程**：**无**。读取仍是既有的 Byte-Offset Tail（同一次 `readlines`），
   写入仍是我方既有的文件追加；未新增线程、未新增定时器、未新增网络。
4. **内存/缓存**：未新增常驻结构（`scene_driven_anim` 一个 bool、`scene_action` 一个信号）。
   **限制（如实说明）**：本次**未做改动前的 A/B CPU 对照**（那需要回滚重跑），故"5.6% 是既有成本"这一句
   是**基于"未新增线程/定时器"的机理判断**，不是对照实测。
